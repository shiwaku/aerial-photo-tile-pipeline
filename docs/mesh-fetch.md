# 図郭データの取得（Step 0）

オルソ画像が「地図上で図郭を選択してダウンロード」形式で公開されている場合、その索引はダウンロード URL を属性に持つベクトルタイルとして配信されていることが多いです。Step 0 はその索引から対象範囲の図郭リストを作り、ZIP を一括ダウンロードして平置き展開します。

手元にデータを配置済みなら Step 0 は不要です。

```bash
cp config/shizuoka-city.conf.example config/shizuoka-city.conf

./scripts/00_build_mesh_list.sh config/shizuoka-city.conf   # Step 0-a: 図郭リスト作成
./scripts/00_fetch_data.sh      config/shizuoka-city.conf   # Step 0-b: 一括ダウンロード
./scripts/run_pipeline.sh       config/shizuoka-city.conf   # Step 1〜5: タイル生成
```

## Step 0-a: 図郭リストを作る

`00_build_mesh_list.sh` は行政境界 GeoJSON（`MESH_BOUNDARY`）または bbox（`MESH_BBOX`）と交差する図郭だけを選びます。

| 出力 | 内容 |
|---|---|
| `output/<id>/mesh_list.csv` | 図郭リスト（`mesh_no,url`）。Step 0-b の入力になる |
| `output/<id>/mesh_polygons.geojson` | 図郭ポリゴン（1 図郭 = 1 フィーチャー） |
| `output/<id>/coverage_outline.geojson` | 整備範囲の外形（範囲確認用） |

大きい自治体は全域で数千〜1 万図郭・数十 GB になります。まず `MESH_NEAR="lon,lat"` ＋ `MESH_COUNT=12` で小さい範囲を通してから全域に広げてください。

```bash
MESH_NEAR="138.3828,34.9756"    # この地点から近い順に
MESH_COUNT="12"                 # N 図郭だけ抽出する
```

`mesh_polygons.geojson` を QGIS で開けば、ダウンロード前に対象範囲を目視確認できます。

## Step 0-b: 一括ダウンロード

`00_fetch_data.sh` は ZIP を並列取得して `SRC_DIR` に平置き展開します。ZIP は `output/<id>/_zip/` に残ります。

```bash
./scripts/00_fetch_data.sh config/<name>.conf --limit 50   # 先頭 50 件だけ取得する
```

展開済みの図郭はスキップするため、中断・再実行に耐えます。並列数は `FETCH_JOBS` で指定しますが、**回線帯域が律速なので増やしても効きません**（単一接続 9.3 MB/s、6 並列 11.2 MB/s、12 並列で実効 67 図郭/分。24 並列にすると 50 図郭/分に低下）。8〜12 が妥当です。

## 索引ベクトルタイルを扱う際の実測メモ

オープンデータでの検証で確認した事実です。新しい索引を扱うときの前提として参照してください。

- 索引タイルは GDAL の MVT ドライバで単体タイルとして開けます。

  ```python
  gdal.OpenEx("MVT:<path>", open_options=["X=", "Y=", "Z=", "CLIP=NO"])
  ```

  返る図形は EPSG:3857 なので EPSG:4326 へ変換してから境界と交差判定します。`CLIP=NO` を付けないとタイル境界で図郭ポリゴンが切られます。

- **低 ZL でも図郭は間引かれていませんでした。** ZL12 の結果が ZL14 の結果を完全に包含しています。ZL12（1 枚あたり約 8km 四方）なら市域規模でも数十枚で済みます。ただしこれはデータセット依存の性質なので、新しい索引を扱うときは高 ZL の結果と集合比較して確かめてください。

- **ダウンロード URL は図郭コードから導出しないでください。** 再撮影分が `<図郭コード>_2.zip` のように別名で配布されている場合があります（検証したデータセットでは 8,840 件中 68 件）。索引の URL 属性をそのまま使います。

- **同じ図郭が複数タイルに現れたらジオメトリを Union します。** ベクトルタイルは各タイル内でジオメトリがクリップされて格納されるため、最初に見つけた 1 枚だけを採用すると境界をまたぐ図郭の外側が欠けます。検証データでは 1,612 図郭が該当し、欠けたポリゴンが境界交差判定から漏れて対象図郭が 4 件不足しました。

- **索引タイルのキャッシュは索引 URL ごとに分けます。** `z/x/y` だけをキーにすると別データセットの索引が同じパスに衝突し、図郭が混ざります。`build_mesh_index.py` は `--cache-dir`（既定 `output/_index_cache/`）の下に索引 URL の SHA1 先頭 10 桁でサブディレクトリを作ります。

- 図郭コードの先頭 2 桁は平面直角座標系の系番号として使われていることが多く、`SRC_SRS` の裏取りに使えます（例: `08...` → 第VIII系 = EPSG:6676）。

- **`NODATA` を安易に設定しないでください。** 図郭が隅まで画像化されている配布形式では余白が存在しません（[`NODATA="auto"` の判定](config.md#nodataauto-の判定)）。

## 動作実績

同梱の設定例は 2 つあります。**同じ静岡市でも別のデータセットで諸元が異なり**、どちらも設定を書き換えずに（`auto` 任せで）通ることを確認しています。

| | `shizuoka-city`（中・西部） | `shizuoka-north`（北部・南アルプス） |
|---|---|---|
| GSD | 0.20 m/px | 0.25 m/px |
| 図郭 | 400×300m（2000×1500px） | 1000×750m（4000×3000px） |
| CRS | 埋め込みなし（TFW のみ） | 埋め込みあり（WKT が非標準なので EPSG で明示） |
| 図郭外の余白 | なし → 透過処理なし | 白 → `255 255 255` を透過 |
| 自動決定した最大 ZL | ZL19 | ZL19 |
| ライセンス | ODbL | CC BY（＋関東森林管理局の承認番号） |
| 静岡市域の図郭数 | 8,844 | 655 |

図郭リスト作成は市全域（8,844 図郭）で 27 秒でした（索引タイル ZL12 を 77 枚取得）。

なお 2 つを合わせると静岡市域の 100%（1,405 / 1,412 km²）をカバーします（中・西部だけでは 72%。北部の山間部が中・西部データセットに含まれない）。両者は 43 km² 重複し、ライセンス表記も異なるため、1 つのタイルセットにまとめる場合は重複域の優先順位と両方の出典表記が必要です。
